# 抖音群聊机器人实现教程

> 本机实现版本，供参考复刻。基于 Playwright CDP + OpenClaw AI。

---

## 一、整体架构

```
Edge浏览器（抖音网页版）
        ↕ CDP 远程调试协议（端口 9222）
douyin_guardian.py（Python主程序）
        ↕ WebSocket
OpenClaw Gateway（本地 AI 网关，端口 18789）
        ↕ HTTP API
AI 模型（豆包 / GPT 等）
```

**核心流程：**
1. Edge 浏览器以调试模式启动，打开抖音网页版并登录到目标群
2. Python 程序通过 CDP 协议连入浏览器，用 Playwright 操控页面
3. 每 2 秒扫描一次页面 DOM，用 `data-bot-seen` 属性标记法识别新消息
4. 发现新消息 → 通过 OpenClaw WebSocket 发给 AI → 等待 AI 流式回复
5. 把 AI 回复通过 Playwright 模拟打字输入到抖音输入框并发送

## 四、消息检测方案（最关键的技术点）

### 为什么不能用内容对比？
抖音 DOM 里的 `innerText` 包含动态内容（点赞数、时间戳等），每次扫描结果不同，跨轮次对比不可靠。

### 最终方案：`data-bot-seen` 属性标记法

```python
# 扫描时，给每个已处理消息的 DOM 节点打上标记
await element.evaluate('el => el.setAttribute("data-bot-seen", "1")')

# 下次扫描时，只处理没有 data-bot-seen 属性的节点
# CSS 选择器：[data-bot-seen] 表示已处理，:not([data-bot-seen]) 表示未处理
```

**优点：**
- 不依赖内容对比，100% 准确
- 标记随 DOM 节点存在，页面不刷新就不会丢失
- 性能好，不需要维护内存 hash 集合

### 抖音 DOM 结构特点

抖音群聊消息有两层嵌套：
```
messageMessageBox（外层容器，包含发送者信息）
  └── contentBox（内层，包含消息文本）
```

连续消息（同一人连续发多条）的结构不同：
- 第一条：有 `messageMessageBox`，包含发送者名字 + `contentBox`
- 后续几条：**只有** `contentBox`，没有外层容器，发送者需要从上一条继承

所以扫描时需要特殊处理：
```python
# 先找父容器 messageMessageBox（带发送者名）
# 同时也要找独立的 contentBox（连续消息）
# 两者都要打 data-bot-seen 标记，防止重复处理
```

## 五、防自回复机制

机器人发出的消息也会出现在 DOM 里，必须识别并跳过，否则会无限循环自问自答。

```python
BOT_IDENTIFIERS = ["天庭号", "天庭", "tianting", "TT", "tt"]

def _is_self_message(self, sender: str) -> bool:
    sender_lower = sender.lower()
    return any(name.lower() in sender_lower for name in self.BOT_IDENTIFIERS)
```

还有内容前缀 hash 去重：机器人发送前记录消息 hash，收到相同 hash 时跳过。

## 七、OpenClaw WebSocket 通信

机器人不直接调用 AI API，而是通过 OpenClaw Gateway 的 WebSocket 接口。

### 认证流程（Ed25519 签名）
```
1. 连接 ws://127.0.0.1:18789/ws
2. 收到 challenge（含 nonce）
3. 用本机设备私钥对 nonce 签名
4. 发送 connect 请求（含签名）
5. 收到 ok 响应，连接建立
```

设备证书存放在：`~/.openclaw/identity/device.json`

### 发送消息
```python
await ws.send(json.dumps({
    "type": "req",
    "method": "agent",
    "params": {
        "message": "用户消息",
        "sessionId": "群聊ID",  # 同一群聊用同一 session，AI 有记忆
        "idempotencyKey": str(uuid.uuid4()),
    }
}))
```

### 接收流式回复
```python
# 三种 stream 类型：
# assistant  → 文字流（delta 字段是增量文字）
# item       → 工具调用结果（通常忽略）
# lifecycle  → 开始/结束/错误状态
while True:
    msg = await ws.recv()
    payload = msg["payload"]
    if payload["stream"] == "assistant":
        reply += payload["data"]["delta"]
    elif payload.get("done"):
        break
```

## 八、发送回复到抖音

通过 Playwright 模拟用户操作：
```python
# 1. 找到输入框并点击聚焦
input_box = await page.query_selector('div[contenteditable="true"]')
await input_box.click()

# 2. 模拟粘贴（比 type 快且稳定）
await page.evaluate(f'''
    const el = document.querySelector('div[contenteditable="true"]');
    el.focus();
    document.execCommand("insertText", false, "{reply}");
''')

# 3. 回车发送
await page.keyboard.press("Enter")
```

## 十一、坑点总结

| 坑 | 解决方案 |
|----|---------|
| 抖音 innerText 含动态内容，内容对比不可靠 | 改用 `data-bot-seen` DOM 标记法 |
| 连续消息没有发送者名字 | 从上一条消息继承发送者 |
| 机器人自己的回复也触发检测 | 多重检查 BOT_IDENTIFIERS + 内容 hash |
| "X人已读"消息触发 AI 调用 | 加入 SYSTEM_MSG_PATTERNS 过滤 |
| AI 回复含 XML 工具调用标签 | 正则清洗：`re.sub(r'<function[^>]*>.*?</function\s*>?', '', ...)` |
| AI 泄露本机路径 | 系统提示词明令禁止 + 后处理 privacy filter |
| OpenClaw WS 连接断开后无法恢复 | 捕获异常后自动重连，最多重试3次 |
| 模型协议不兼容（GPT-5.5 需要 Responses API） | 换用 `gpt-5.4-openai-compact` |
