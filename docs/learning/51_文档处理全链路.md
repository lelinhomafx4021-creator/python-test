# 51_文档处理全链路：解析 → 分块 → 向量化 → 入库

> **核心问题**: 一份 PDF 怎么变成 Agent 能检索到的知识
> **项目代码**: `app/rag/parser.py` + `app/rag/chunker.py` + `app/rag/vector_store.py`

---

## 一、完整链路

```
PDF/DOCX/MD 文件
    │
    ▼
① 解析（parser.py）           → 提取纯文本
    │
    ▼
② 分块（chunker.py）          → 切成 500 字的小块，重叠 50 字
    │
    ▼
③ 向量化（vector_store.py）   → 每块文本 → 1024 维向量
    │
    ▼
④ 入库（vector_store.py）     → 写入 pgvector 的 doc_chunks 表
    │
    ▼
⑤ 检索（retriever_tool.py）   → 用户 query → 向量 → SQL <=> 查最相似的块
```

## 二、第 1 步：文档解析

```python
# app/rag/parser.py
from langchain_community.document_loaders import PyPDFLoader, Docx2txtLoader

def load_documents(file_path: str) -> list:
    if file_path.endswith('.pdf'):
        loader = PyPDFLoader(file_path)
    elif file_path.endswith('.docx'):
        loader = Docx2txtLoader(file_path)
    else:
        raise ValueError(f"不支持的文件类型: {file_path}")
    return loader.load()
# 返回 [Document(page_content="...", metadata={"source": "xxx.pdf", "page": 1})]
```

**PDF 的坑**：扫描件 PDF（图片）PyPDFLoader 读不出来。这时候需要 OCR（pytesseract）。

## 三、第 2 步：文本分块

### 3.1 为什么分块

```
不分块:
  一整本 PDF 的 50000 字 → 一个 1024 维向量
  检索精度极低——50000 字里只有 200 字是用户要的，但向量表示的是"整本书"

分块后:
  50000 字 → 100 块 × 500 字 → 100 个 1024 维向量
  检索精确到"块"——用户搜"茅台净利润"，命中"包含茅台净利润的那几块"
```

### 3.2 chunk_size 和 chunk_overlap 怎么选

```
chunk_size=500：每块 500 字。太大噪音多，太小信息碎片化
chunk_overlap=50：相邻两块重叠 50 字

为什么需要 overlap：

不重叠：
  块1: "贵州茅台2024年营收增长"    ← 这句话被切成两半
  块2: "15.2%，净利润增长12.8%"     ← 后半句在下一块

  用户搜"茅台营收增长" → 命中块1 → 但块1只有前半句"贵州茅台2024年营收增长"
  → 没 context，不知道营收到底增长了多少

有 overlap：
  块1: "贵州茅台2024年营收增长15.2%，净利润"
  块2: "营收增长15.2%，净利润增长12.8%"
  → 不管搜到哪一块，都有完整信息
```

### 3.3 代码

```python
# app/rag/chunker.py
from langchain.text_splitter import RecursiveCharacterTextSplitter

text_splitter = RecursiveCharacterTextSplitter(
    chunk_size=500,       # 每块最多 500 字符
    chunk_overlap=50,     # 重叠 50 字符
    length_function=len,
    # 按优先级分隔：先段落 → 再句子 → 再逗号 → 最后字符级
    separators=["\n\n", "\n", "。", "！", "？", "；", "，", " ", ""]
)

chunks = text_splitter.split_documents(documents)
```

**`separators` 的优先级**：首选在段落边界切（保留语义完整性），不行就句子边界，再不行就逗号。越前面的分隔符越优先。

### 3.4 进阶：语义分块（Semantic Chunking）

固定大小分块的问题是"在句子中间断开"。语义分块不按字符数切——按"什么时候话题变了"切：

```python
from langchain_experimental.text_splitter import SemanticChunker

splitter = SemanticChunker(
    embeddings=OpenAIEmbeddings(),
    breakpoint_threshold_type="percentile",
    breakpoint_threshold_amount=90,  # 相邻两句相似度低于 90 百分位 → 切
)
```

**原理**：计算相邻句子的 embedding 相似度。相似度骤降的地方就是话题边界——这里切开。

### 3.5 进阶：上下文增强（Contextual Retrieval）

Anthropic 2024 年提出的技巧，实测检索精度提升 35-50%：

```python
# 每块前面加一句"这份文档是关于...的"
original = "净利润747亿元，同比增长15.2%"

enhanced = (
    "【文档】贵州茅台2024年年报，财务数据章节。"
    "【内容】净利润747亿元，同比增长15.2%"
)
# LLM 检索到这段时知道它出自茅台年报的财务章节，不是新闻或研报
```

### 3.6 分块策略选型

| 策略 | 精度 | 成本 | 适用 |
|------|------|------|------|
| 固定大小（项目在用） | 中 | 零 | 通用文档，快速启动 |
| 语义分块 | 高 | 低（需 embedding） | 长文、对话记录 |
| 上下文增强 | 提升 35-50% | 低 | **任何场景都能叠加** |

## 五、第 4 步：入库

```python
# UPSERT: 如果 id 冲突就跳过（不重复入库同一条）
INSERT INTO doc_chunks (id, content, source, page, chunk_index, file_type, embedding)
VALUES (%s, %s, %s, %s, %s, %s, %s)
ON CONFLICT (id) DO NOTHING
```

## 六、第 5 步：检索

```sql
-- 用户 query 先被向量化成 query_vec
-- 然后查最相似的 top_k 个块
SELECT content, source, page,
       1 - (embedding <=> $1::vector) AS score   -- 余弦相似度
FROM doc_chunks
ORDER BY embedding <=> $1::vector
LIMIT $2
```

## 七、面试速记

**Q: chunk_size 怎么选？**
A: 通用推荐 256-512。太小（128）检索到的内容碎片化——用户看到的是半句话。太大（2048）检索精度下降——一块里太多无关内容。overlap 取 chunk_size 的 10-20%，保证跨块边界的信息完整。

**Q: 扫描件 PDF 怎么处理？**
A: PyPDFLoader 只能读文字 PDF。扫描件需要用 OCR（pytesseract + pdf2image 把每页转成图片再识别文字）。如果 PDF 混合了文字页和扫描页，两套方案组合用。

**Q: 入库后怎么知道有没有重复？**
A: 用 source + file_hash 做去重。`ai_ingest_registry` 表记录了每个文件的 hash。同一个文件重新入库时，先删掉旧 chunks（`DELETE WHERE source = 'xxx.pdf'`），再写新的。`ON CONFLICT (id) DO NOTHING` 是最后一道防线。
