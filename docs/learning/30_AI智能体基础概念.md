## 一、Agent = LLM + 记忆 + 工具 + 决策循环

### 1.1 传统程序 vs Agent 程序：一个例子看清区别

```
任务："帮我查一下茅台今天的股价，如果涨了就告诉我最近有什么利好消息"

传统程序（你写死每一步）：
  def check_stock(query):
      code = extract_code(query)           # 你写正则提取股票代码
      price = call_quote_api(code)         # 你写 HTTP 调用
      change = price["change_percent"]
      if change > 0:                       # 你写 if-else
          news = call_news_api("茅台")      # 你决定调哪个 API
          return format(price, news)        # 你写格式化逻辑
      return format(price)

Agent 程序（你只给能力，LLM 决定怎么做）：
  agent = Agent(
      llm=ChatOpenAI(...),
      tools=[get_quote, get_news],     # 给工具，不给顺序
  )
  agent.invoke("茅台今天股价？涨了就查利好")

# Agent 自己决策：
# Step 1: 需要查股价 → 调 get_quote("600519") → 拿到 {price: 1856, change: +2.3%}
# Step 2: 涨了 → 需要查利好 → 调 get_news("茅台") → 拿到新闻列表
# Step 3: 综合回答
```

### 1.2 四个组件拆解

| 组件 | 做什么 | 类比 | 项目代码 |
|------|--------|------|---------|
| **LLM** | 理解意图、推理决策 | 大脑 | `app/core/llm.py` — `get_llm()` |
| **记忆** | 记住对话历史和中间结果 | 便签本 | `app/graph/state.py` — `AgentState`（18字段） |
| **工具** | 执行具体操作：搜索、查行情、算数据 | 手和脚 | `app/tools/` — retriever、stockdata、data_fetcher |
| **决策循环** | 观察→思考→行动→再观察，直到完成任务 | 工作习惯 | `app/graph/investor_graph.py` — LangGraph 图引擎 |

### 1.3 Agent 的执行循环（ReAct 模式）

```
┌─────────────────────────────────────────────┐
│              Agent 执行循环                   │
│                                              │
│  用户输入 ──→ [观察] ──→ [思考] ──→ [行动]   │
│                ↑                      │      │
│                │                      ↓      │
│                └──── [观察结果] ←─────┘      │
│                           │                  │
│                           ↓                  │
│                      [可以回答了?]            │
│                      /          \            │
│                    是            否           │
│                    ↓             └→ 继续循环  │
│                 [输出回答]                    │
└─────────────────────────────────────────────┘

具体例子：
  用户: "茅台股价多少"
  → 观察: 收到用户问题
  → 思考: 需要查股价，应该调 get_quote 工具
  → 行动: 调 get_quote("600519")
  → 观察: 拿到 {price: 1856, change: +2.3%}
  → 思考: 数据够了，可以回答
  → 输出: "茅台(600519)当前1856元，涨2.3%"
```

## 三、什么时候不该用 Agent（成本意识）

Agent 不是银弹。每次决策都在消耗 Token。

```
场景对比：

✅ 该用 Agent：
  "帮我分析茅台的财报，对比行业平均，给出投资建议"
  → 需要多步推理、查多种数据源、综合分析
  
  "帮我订一张下周五去上海的机票，要早上的，价格不超过 1500"
  → 需要查航班、比价格、做决策

❌ 不该用 Agent（直接用 LLM 或传统 API 就行）：
  "你好" → 不需要推理和工具
  "茅台股价" → 一次 API 调用就解决，不需要 Agent 循环
  "把这段文本翻译成英文" → 单轮 LLM 调用即可
```

**原则**：Agent 的价值在"需要多步推理 + 调用外部工具"。简单任务用 Agent 是浪费。

## 四、你的第一个 Agent：10 行代码跑起来

```python
"""
把上面的概念变成能跑的代码。
安装: pip install langchain langchain-openai
"""

from langchain.agents import create_agent
from langchain.chat_models import init_chat_model

# ===== 1. 定义工具（手和脚）=====
def get_stock_price(stock_code: str) -> str:
    """查询股票实时价格。stock_code 如 '600519'"""
    prices = {"600519": "1856元", "000858": "142元", "002594": "245元"}
    return prices.get(stock_code, "未找到该股票")

def get_hot_news(topic: str) -> str:
    """搜索相关新闻。topic 如 '茅台'"""
    return f"关于{topic}的最新新闻：行业景气度回升，北向资金持续流入。"

# ===== 2. 创建 Agent（大脑 + 手脚 + 决策循环）=====
agent = create_agent(
    model=init_chat_model("openai:gpt-4o-mini"),  # 大脑
    tools=[get_stock_price, get_hot_news],         # 手脚
    system_prompt="你是股票助手，回答简短专业。",
)

# ===== 3. 运行 =====
result = agent.invoke({
    "messages": [{"role": "user", "content": "茅台股价多少？涨了的话查查利好新闻"}]
})

# LLM 自己做决策:
#   Step 1: 调 get_stock_price("600519") → "1856元"
#   Step 2: 判断 "涨了没有？" → 假设当前高于上次收盘 → 涨了
#   Step 3: 调 get_hot_news("茅台") → "行业景气度回升..."
#   Step 4: 综合回答用户

print(result["messages"][-1].content)
# "茅台(600519)当前1856元。近期利好消息：行业景气度回升，北向资金持续流入。"
```

**这 10 行代码包含了 Agent 的所有核心组件**：

```
LLM（大脑）     → init_chat_model("gpt-4o-mini")
记忆（便签本）   → create_agent 内置的消息历史（不用你管）
工具（手脚）     → [get_stock_price, get_hot_news]
决策循环（习惯） → create_agent 内部的 ReAct 循环（不用你写 while）
```

## 五、自己手写 ReAct 循环：理解 Agent 内部怎么跑

`create_agent` 帮你封装了循环。但面试时你要能说清楚内部做了什么：

```python
"""手写最简 ReAct 循环：7 个步骤"""
import json

# 工具定义（JSON Schema 格式，和 MCP 一样）
TOOLS = [
    {
        "type": "function",
        "function": {
            "name": "get_stock_price",
            "description": "查询股票实时价格",
            "parameters": {"type": "object", "properties": {"stock_code": {"type": "string"}}, "required": ["stock_code"]}
        }
    }
]

# 实际的工具函数
def execute_tool(name, args):
    if name == "get_stock_price":
        return f"{args['stock_code']} 当前 1856元，涨幅 +2.3%"

messages = [{"role": "user", "content": "茅台股价多少"}]
llm = init_chat_model("openai:gpt-4o-mini")

# ═══ ReAct 循环 ═══
MAX_TURNS = 5
for turn in range(MAX_TURNS):

    # ① 调 LLM（带工具定义）
    response = llm.invoke(messages, tools=TOOLS)

    # ② LLM 想调工具？
    if response.tool_calls:
        for tc in response.tool_calls:
            # ③ 你的代码执行工具
            result = execute_tool(tc["name"], json.loads(tc["arguments"]))

            # ④ 把执行结果发回给 LLM
            messages.append({"role": "tool", "tool_call_id": tc["id"], "content": result})

    # ⑤ LLM 直接回答 → 结束循环
    else:
        messages.append({"role": "assistant", "content": response.content})
        break

print(messages[-1]["content"])
# "茅台(600519)当前1856元，涨幅+2.3%。"
```

**`create_agent` 内部的循环就是这段代码。你不写，框架帮你写了而已。**

## 七、面试速记

**Q: Agent 和普通 LLM 调用有什么区别？**
A: 普通 LLM 调用是"一问一答"——发 prompt → 等回答。Agent 是"多轮决策循环"——观察→思考→调工具→看结果→再思考→...→最终回答。Agent 能自主决定使用什么工具、按什么顺序、什么时候可以给出最终答案。

**Q: Agent 的四个组件？**
A: LLM（大脑，做决策）、记忆（记住上下文和中间状态）、工具（执行具体操作）、决策循环（观察-思考-行动-再观察）。四个组件缺一不可——少了任何一个都不是 Agent。

**Q: 什么时候不该用 Agent？**
A: 简单任务不需要——"查股价"一次 API 调用就够，Agent 循环反而浪费 Token。Agent 的价值在"需要多步推理 + 调度多个工具"。面试加点分：成本意识是区分工程师成熟度的标志。

**Q: 市面上主流 Agent 框架怎么选？**
A: LangGraph 手写 StateGraph 适合需要完全控制的复杂场景（本项目）。create_agent 适合标准 tool-calling 循环。AutoGen 适合微软生态。CrewAI 适合角色扮演式多 Agent。了解它们的差异比会用一个重要。
