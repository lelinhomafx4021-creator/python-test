# 47_A2A协议详解：Agent 和 Agent 怎么对话

> **核心目标**: 理解 A2A 和 MCP 的分工——MCP 管 Agent↔Tool，A2A 管 Agent↔Agent
> **项目关联**: 项目目前单 Agent，不需要 A2A。但面试必问"项目怎么扩展到多 Agent"。

---

## 一、MCP 和 A2A 各管什么

MCP 和 A2A 是 AI 世界两套互补的通信标准，由两家公司各自主导：

| | MCP（Anthropic 主导） | A2A（Google 主导） |
|------|------|------|
| **全称** | Model Context Protocol | Agent-to-Agent Protocol |
| **谁和谁通信** | AI ↔ 工具/数据源 | Agent ↔ Agent |
| **场景** | LLM 调天气 API、读文件、查数据库 | 研究员 Agent 把结果交给分析师 Agent |
| **协议** | JSON-RPC 2.0 | HTTP + JSON（REST-like） |
| **发现机制** | `tools/list` | Agent Card（一个 JSON 文件，描述 Agent 的能力） |

**一句话**：MCP 是 AI 的"手"——连接外部工具。A2A 是 AI 的"嘴"——连接其他 AI。

---

## 二、A2A 的核心：Agent Card

每个 A2A Agent 暴露一个 `/.well-known/agent.json` 端点，返回它的"名片"：

```json
// GET https://researcher-agent.example.com/.well-known/agent.json
{
    "name": "投研研究员 Agent",
    "description": "搜索和整理投研资料。不分析，只找资料。",
    "url": "https://researcher-agent.example.com",
    "version": "1.0.0",
    "capabilities": {
        "streaming": true,
        "pushNotifications": false
    },
    "skills": [
        {
            "id": "research",
            "name": "投研搜索",
            "description": "根据查询搜索相关研报、财报、新闻",
            "inputSchema": {
                "type": "object",
                "properties": {
                    "topic": {"type": "string", "description": "搜索主题"},
                    "depth": {"type": "string", "enum": ["quick", "detailed"]}
                },
                "required": ["topic"]
            }
        }
    ],
    "defaultInputModes": ["text"],
    "defaultOutputModes": ["text"]
}
```

**Agent Card = MCP 的 `tools/list` + `resources/list` 的合体**，但格式不同，面向的是 Agent 而不是 LLM。

## 三、A2A 的任务模型

A2A 的核心概念是 **Task（任务）**——一个 Agent 发给另一个 Agent 的"活儿"。

```
① 客户端发 POST /tasks
{
    "id": "task-001",
    "sessionId": "session-abc",
    "message": {
        "role": "user",
        "parts": [{"type": "text", "text": "帮我搜一下茅台2024年的财报数据"}]
    }
}

② 服务端返回 202 Accepted
{
    "id": "task-001",
    "state": "submitted"   // submitted → working → completed / failed
}

③ 客户端轮询 /tasks/task-001 查询状态
{
    "id": "task-001",
    "state": "completed",
    "artifacts": [
        {
            "name": "research_result.json",
            "parts": [{"type": "text", "text": "茅台2024年净利润747亿，同比增长15.2%..."}]
        }
    ]
}
```

**A2A 是异步的**：发任务 → 收到"收到" → 轮询查状态 → 拿到结果。不像 MCP 的 `tools/call` 是同步的（等执行完才返回）。

## 四、可运行的 A2A 服务端 + 客户端

### 4.1 A2A 服务端（你暴露给外部的 Agent）

```python
"""
a2a_server.py — 最简 A2A 服务端
暴露你的投研 Agent 给外部 Agent 调用
"""
from fastapi import FastAPI
from pydantic import BaseModel
import uuid
import time

app = FastAPI()

# ===== Agent Card: 描述你能干什么 =====
@app.get("/.well-known/agent.json")
async def agent_card():
    return {
        "name": "投研分析 Agent",
        "description": "分析股票，输出研究报告",
        "url": "https://your-agent.example.com",
        "version": "1.0.0",
        "capabilities": {"streaming": True},
        "skills": [
            {
                "id": "analyze_stock",
                "name": "股票分析",
                "description": "分析指定股票的技术面、基本面、新闻舆情",
                "inputSchema": {
                    "type": "object",
                    "properties": {
                        "stock_code": {"type": "string"},
                        "depth": {"type": "string", "enum": ["quick", "detailed"]}
                    },
                    "required": ["stock_code"]
                }
            }
        ]
    }

# ===== 任务存储（生产环境用数据库）=====
tasks = {}

class TaskRequest(BaseModel):
    id: str
    message: dict

@app.post("/tasks")
async def create_task(req: TaskRequest):
    """接收任务——异步模式，先返回'收到了'"""
    tasks[req.id] = {
        "id": req.id,
        "state": "submitted",
        "message": req.message,
        "created_at": time.time(),
    }
    # ... 实际项目里这里触发 Agent 异步执行 ...
    return {"id": req.id, "state": "submitted"}

@app.get("/tasks/{task_id}")
async def get_task(task_id: str):
    """轮询任务状态"""
    task = tasks.get(task_id)
    if not task:
        return {"error": "task not found"}, 404
    return task

# 启动: uvicorn a2a_server:app --port 8000
```

### 4.2 A2A 客户端（你的 Agent 调外部 Agent）

```python
"""
a2a_client.py — 你的 Agent 调外部 A2A 服务
"""
import httpx
import time
import asyncio

class A2AClient:
    def __init__(self, base_url: str):
        self.base_url = base_url

    async def discover(self) -> dict:
        """第一步: 看外部 Agent 的名片——它能干什么"""
        async with httpx.AsyncClient() as client:
            resp = await client.get(f"{self.base_url}/.well-known/agent.json")
            return resp.json()
        # 返回: {"name": "投研分析Agent", "skills": [{...办法分析股票}]}

    async def send_task(self, message: str) -> str:
        """第二步: 发任务 → 轮询结果"""
        task_id = f"task-{str(uuid.uuid4())[:8]}"
        async with httpx.AsyncClient() as client:

            # ① 发任务
            await client.post(
                f"{self.base_url}/tasks",
                json={
                    "id": task_id,
                    "message": {"role": "user", "parts": [{"type": "text", "text": message}]}
                }
            )

            # ② 轮询直到完成
            for _ in range(60):  # 最多等 60 秒
                await asyncio.sleep(1)
                resp = await client.get(f"{self.base_url}/tasks/{task_id}")
                data = resp.json()

                if data["state"] == "completed":
                    return data["artifacts"][0]["parts"][0]["text"]
                elif data["state"] == "failed":
                    return f"任务失败: {data.get('error', '未知错误')}"

            return "任务超时"


# ===== 使用: 你的 Agent 调用外部 Agent =====
async def main():
    # 发现外部 Agent
    client = A2AClient("https://投研分析-agent.公司.com")
    card = await client.discover()
    print(f"发现 Agent: {card['name']}")
    print(f"  技能: {[s['name'] for s in card['skills']]}")

    # 委托任务
    result = await client.send_task("帮我分析茅台(600519)，输出投资建议")
    print(f"外部 Agent 返回: {result}")

asyncio.run(main())
```

### 4.3 A2A vs 直接 HTTP 调用

```python
# A2A 做的事就是 HTTP 请求。那直接发 HTTP 不行吗？

# 直接 HTTP:
resp = requests.post("https://外部服务/api/analyze", json={"stock": "600519"})

# A2A:
agent_card = requests.get("https://外部服务/.well-known/agent.json")  # 先看名片
task = requests.post("https://外部服务/tasks", json={...})            # 发任务
result = requests.get(f"https://外部服务/tasks/{task.id}")            # 轮询

# A2A 比直接 HTTP 多做了什么？
# 1. 标准化的"名片"——Agent 不需要提前知道对方有什么 API
# 2. 标准的任务模型——异步任务统一接口
# 3. 统一的错误格式
# 本质上就是 HTTP，只是规定了格式。和 MCP 一样——"标准协议包裹的普通调用"。

## 五、面试速记

**Q: A2A 和 MCP 什么关系？**
A: 互补不是竞争。MCP（Anthropic 主导）管 Agent↔Tool，用 JSON-RPC，同步调用。A2A（Google 主导）管 Agent↔Agent，用 Agent Card 发现 + Task 异步执行。同一个系统里可能同时用——Agent 通过 A2A 委托任务给另一个 Agent，被委托的 Agent 通过 MCP 调用工具完成任务。

**Q: 你们项目用 A2A 吗？**
A: 目前单 Agent 架构不需要。如果将来拆成多个专用 Agent（研究员 / 分析师 / 写手），Agent 之间可以用 A2A 协议通信。但同项目内直接 import 调用更简单——A2A 的异步开销在本地场景不划算。
