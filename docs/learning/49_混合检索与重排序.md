# 49_混合检索与重排序：向量 + BM25 + RRF + Reranker

> **核心问题**: 向量检索能找到语义相似的但漏掉精确匹配的，BM25 相反。你两个都要。

## 一、单一检索的盲区

```
用户搜索: "2024Q3 财报 GAAP 净利润"

向量检索（语义相似）:
  找到: "2024年第三季度财务报告中的利润数据..."
  漏掉: 没有——向量检索理解了"Q3=第三季度"、"GAAP=会计准则"
  ✅ 擅长语义理解

BM25（关键词匹配）:
  找到: "2024Q3 GAAP 净利润为 747 亿元..."
  漏掉: 没有——BM25 精确匹配了"2024Q3"和"GAAP"
  ✅ 擅长精确匹配
```

**两个都用 = 互补盲区。**

## 二、RRF（Reciprocal Rank Fusion）—— 怎么把两路结果合并

### 2.1 公式

```
RRF_score(d) = Σ 1 / (k + rank_i(d))

  d: 文档
  rank_i(d): 文档 d 在第 i 路检索中的排名（1 = 第一名）
  k: 平滑参数（通常 60，排名越高受 k 影响越小）
  Σ: 所有检索路的分数求和
```

### 2.2 为什么不用加权平均

```
向量得分: 0.92（余弦相似度，范围 0~1）
BM25 得分: 23.7（相关性分数，范围 0~无穷）

这两个数字不能直接加权——值域不同。
RRF 不关心原始分数，只关心排名。排第一就是第一，不管"分数多少"。
```

### 2.3 计算过程

```
文档 A 在两路检索中的排名:
  向量检索排名: 第 1 名 → 1/(60+1) = 0.0164
  BM25 检索排名: 第 3 名 → 1/(60+3) = 0.0159
  RRF 总分 = 0.0164 + 0.0159 = 0.0323

文档 B 在两路检索中的排名:
  向量检索排名: 第 5 名 → 1/(60+5) = 0.0154
  BM25 检索排名: 第 1 名 → 1/(60+1) = 0.0164
  RRF 总分 = 0.0154 + 0.0164 = 0.0318

文档 A 总分 > 文档 B → A 排在 B 前面
虽然 A 在 BM25 只排第 3，但向量排第 1 拉上来了。
```

### 2.4 代码

```python
def rrf_fusion(vector_results, bm25_results, k=60):
    """RRF 融合两路检索结果"""
    scores = {}

    # 第一路：向量检索
    for rank, doc in enumerate(vector_results, start=1):
        doc_id = doc["id"]
        scores[doc_id] = scores.get(doc_id, 0) + 1 / (k + rank)

    # 第二路：BM25
    for rank, doc in enumerate(bm25_results, start=1):
        doc_id = doc["id"]
        scores[doc_id] = scores.get(doc_id, 0) + 1 / (k + rank)

    # 按总分降序排列
    return sorted(scores.items(), key=lambda x: x[1], reverse=True)
```

## 四、重排序（Reranking）：检索后再精排

### 4.1 为什么要 Rerank

```
检索阶段（粗排）:
  向量检索 Top-20 → 速度快但精度一般（ANN=近似最近邻）

Rerank 阶段（精排）:
  把 Top-20 扔给一个更强的 Cross-encoder 模型 → Top-5
  每条都真正和 query 做配对计算，精度远高于向量相似度
```

### 4.2 代码

```python
# pip install cohere
import cohere
co = cohere.Client("your-api-key")

# 检索: 拿到 20 条候选
candidates = vector_store.search(query, top_k=20)

# Rerank: 用 Cohere 的模型重新打分，只保留前 5
rerank_result = co.rerank(
    query=query,
    documents=[doc["text"] for doc in candidates],
    top_n=5,
    model="rerank-v3.5"       # Cohere 的重排序模型
)

# 按新分数重排
reranked = [candidates[item.index] for item in rerank_result.results]
```

### 4.3 效果

```
不 Rerank:
  Top-5 向量检索结果 → 可能第 3 条和第 5 条其实不太相关

Rerank 后:
  Top-5 中真正相关的排到前面，不太相关的被挤出去
  召回率提升 10-20%，但多了 1 次 API 调用（~100ms）
```

## 五、面试速记

**Q: 混合检索怎么做？**
A: 向量检索（语义相似）+ BM25（关键词匹配）双路并行，用 RRF（倒数排名融合）合并——排第一就是第一，不关心不同数据源的原始分数值域不同。可选加第三路联网检索和 Reranker 精排。

**Q: RRF 为什么不用加权平均？**
A: 向量分数是 0~1 的相似度，BM25 分数是 0~无穷的相关性——两个值域不同的数没法直接加权。RRF 不关心原始分数，只看排名。k=60 是经验值，排名越高受 k 影响越小。

**Q: 你们项目的检索策略是什么？**
A: 目前是"先本地 pgvector，没命中再联网"的降级策略。计划升级到向量+BM25 混合检索 + RRF 融合。因为降级策略在本地有结果时完全放弃了 BM25 的精确匹配能力和联网的最新资讯。
