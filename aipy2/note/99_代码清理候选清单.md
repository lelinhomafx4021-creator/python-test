可以考虑统一清理项目源码目录下的 `__pycache__`，例如：

1. `aipy2/app/**/__pycache__`

- 可以清项目源码目录下的缓存
- 不建议动 `.venv` 里的缓存作为常规手工清理目标

## 3. 不建议现在删除的文件类别

### 3.1 初始化和数据库基础设施

1. `app/core/db.py`
2. `alembic/*`
3. `main.py` 里的生命周期初始化
4. `vector_store.py` 相关建表和索引逻辑

原因：它们属于系统基础设施，不是普通死代码。

### 3.2 图编排和状态核心

1. `app/graph/*`
2. `app/prompts/*`
3. `app/services/*`

原因：这是 Agent 主大脑。

### 3.3 能力层

1. `app/tools/*`
2. `app/skills/*`
3. `scripts/ingest_docs.py`
4. `scripts/init_chat_history.py`

原因：看起来像“偶尔用到”，但它们分别承担检索、行情、知识库导入、历史数据初始化等职责。

## 4. 后续更稳的清理策略

如果后面要继续瘦身，我建议按这个顺序：

1. 先删日志
2. 再删缓存
3. 再删废弃临时脚本
4. 然后列出“空目录/占位包”让你确认
5. 最后才碰业务代码，而且必须先做引用扫描

## 5. 这一份清单的意义

这份清单的核心价值不是“赶紧删”，而是帮助我们建立一个清晰边界：

- 哪些是临时垃圾
- 哪些是扩展位
- 哪些是主链路基础设施

## 6. 当前结论

1. 真正安全可删的，主要是日志和缓存。
2. `app/agents/` 这类空包更像预留位，不建议现在动。
3. 这个项目当前最重要的不是继续大面积删，而是先把 Agent 学透。
