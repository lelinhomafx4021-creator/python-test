# 02 入口、配置与启动

## 1. `main.py` 为什么重要

`main.py` 不是写业务逻辑的地方，而是整个 Python 服务的装配入口。

它通常负责：

1. 创建 FastAPI 应用
2. 注册路由
3. 注册中间件
4. 定义生命周期初始化逻辑

这和 Java 里 `SpringBootApplication` 的角色非常像。

## 2. 生命周期 `lifespan` 在做什么

这个项目里 `lifespan` 非常关键，因为 Agent 项目通常要在启动阶段准备资源。

这里会做的事包括：

1. 初始化 LLM 相关组件
2. 初始化 checkpoint 连接池
3. 准备向量表和索引

这不是“可有可无”的初始化，而是系统主链路能否跑起来的前置条件。

## 3. 为什么初始化代码不能乱删

这类代码有个共同特点：

1. 平时不总在业务链路里显眼出现
2. 但没有它系统会在启动阶段或第一次请求时出问题

所以：

- 业务代码是“运行时显性依赖”
- 初始化代码是“生命周期级依赖”

这也是之前我们吸取到的一个很重要的经验。

## 4. `.env`、`.env.example`、`config.py` 的关系

### 4.1 `.env`

真实运行时配置文件，程序真正读取它。

### 4.2 `.env.example`

模板文件，给团队说明这个项目需要哪些环境变量。

### 4.3 `config.py`

把环境变量读进 Python 对象，统一交给业务代码使用。

你可以把它理解成“配置中心的类型化门面”。

## 5. 为什么不直接在代码里写 key

直接把 key 写死在业务文件里会有很多问题：

1. 不安全
2. 不方便换环境
3. 难以切换模型供应商
4. 难以本地开发和线上部署共存

所以工程项目都会把这些东西抽到配置层。

## 6. 当前 Python 项目最关键的配置项

1. `DATABASE_URL`
2. `DEEPSEEK_API`
3. `SEARCHER_API`
4. `SEARCHER_API_URL`
5. `LANGFUSE_*`
6. `APP_ENV`

这些配置对应了：

- 数据库
- LLM
- 搜索工具
- 观测系统
- 环境模式

## 7. 启动脚本的价值

像 `start_dev.ps1` 这种脚本看起来简单，但它的价值在于：

1. 固定启动端口
2. 固定 reload 参数
3. 固定开发模式
4. 降低手动命令输错的概率

所以启动脚本不是冗余，而是“开发体验基础设施”。

## 8. `trace_id` 和中间件为什么值得学

中间件里常见会做：

1. 给每个请求生成 `trace_id`
2. 记录耗时
3. 写日志
4. 在响应头回传

这样做的意义是：

- 出错时能串联日志
- 能定位某次请求的完整轨迹
- 后面接 LangFuse / tracing 会更方便

## 9. 这一篇你最该记住的结论

1. `main.py` 是装配层，不是业务层。
2. 初始化逻辑是 Agent 项目的命门，不能随便删。
3. 配置层存在的目的，是把运行环境差异从业务代码里隔离出去。
