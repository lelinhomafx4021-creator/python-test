# 13 代码阅读实战清单

## 1. 这篇是干什么的

前面的笔记在讲知识，这篇讲“你回头怎么真正读代码”。

目标不是看完所有文件，而是建立一个实战阅读路线，让你能一边看一边确认自己到底懂了没有。

## 2. 第一步：只看入口，不看细节

打开这几个文件：

1. `main.py`
2. `app/api/v1/chat.py`
3. `app/services/investor_service.py`

你只回答三个问题：

1. 请求从哪里进来
2. 谁把请求交给 Agent
3. 谁负责最后把响应返回给前端

如果这三问答不出来，就先不要进 graph。

## 3. 第二步：只看 Graph 框架，不看每个 prompt

打开：

1. `app/graph/investor_graph.py`

你重点找：

1. `AgentState`
2. 节点函数有哪些
3. 边和条件路由怎么连
4. 最终是怎么 compile 的

这一步你的目标不是看懂每个细节，而是画出图。

## 4. 第三步：逐个节点看“输入 -> 输出”

对每个节点都问自己：

1. 它读了 `state` 里的什么字段
2. 它写回了什么字段
3. 它有没有调 LLM
4. 它有没有调 tool/skill

这是读 Agent 代码最有效的方法之一。

## 5. 第四步：只看一个能力层，不要全看

建议先选一个：

1. `retriever_tool.py`
2. `stock_analysis_skill.py`
3. `vector_store.py`

先只啃一个，不要三份一起看。

不然很容易因为底层细节太多而断掉整体感。

## 6. 第五步：顺着一次真实问题手推

拿一个实际问题，比如：

`请简要分析贵州茅台的投资看点`

然后手推：

1. `intent` 会怎么判
2. 会不会走 `use_kb`
3. `rewrite` 会产生什么查询
4. `search` 大概会调哪些能力
5. `answer` 会用哪些知识
6. `critic` 可能怎么评价

这种“手推流程”比死看代码效率高很多。

## 7. 第六步：反着读异常和坑

等你主线懂了，再去看问题案例：

1. 为什么 `messages[-1]` 会出 bug
2. 为什么 Windows 下 emoji 会触发 `GBK` 报错
3. 为什么同步 `requests.get()` 放进 async 链路会有风险

这一步能帮你把“能看懂”升级为“能排障”。

## 8. 一套非常实用的阅读提问模板

读每个文件都问：

1. 这层为什么存在
2. 这层向上提供什么能力
3. 这层向下依赖什么能力
4. 这层最关键的数据结构是什么
5. 这层最怕哪类 bug

如果你养成这个习惯，读代码会越来越快。

## 9. 建议你做的三个练习

### 练习一

自己画一张“前端 -> Java -> Python -> Graph -> Tool -> DB”的图。

### 练习二

不用看文档，自己口头解释一次 `AgentState`。

### 练习三

自己解释“为什么当前项目不是严格多智能体”。

## 10. 这一篇你最该记住的结论

1. 看 Agent 代码不能平均用力，要沿调用链看。
2. 先看层级，再看节点，再看能力层，最后看异常案例。
3. 真正的读懂，不是看过文件，而是能自己手推一次完整流程。
