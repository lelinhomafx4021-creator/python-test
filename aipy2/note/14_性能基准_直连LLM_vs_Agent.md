# 14 性能基准：直连 LLM vs 完整 Agent

更新时间：2026-04-26

## 1. 测试目标

验证“回答慢”到底主要来自哪里：

1. 模型本身生成慢
2. 还是我们的 Agent 架构额外引入了明显开销

## 2. 测试方法

为了尽量排除 HTTP 和前端影响，这次测试直接在 Python 进程内做两组对比：

### 2.1 直连 LLM

直接调用 `get_llm(...).astream(...)`

### 2.2 完整 Agent

直接调用 `investor_service.run_investor_flow(...)`

这样测到的“架构开销”主要来自：

1. LangGraph 节点调度
2. intent / rewrite / search / answer / critic
3. 流式事件组装
4. RAG 与工具调用

而不是来自：

1. Java 网关
2. 浏览器
3. 前端渲染

## 3. 测试问题

### 简单问题

`请用中文简单自我介绍一下，不超过80字。`

### 投研问题

`请用中文分3点简要分析贵州茅台的投资看点，每点一句。`

## 4. 测试结果

### 4.1 简单问题

#### 直连 LLM

- 首 token：约 `3840ms`
- 总耗时：约 `4535ms`

#### 完整 Agent

- 第一条步骤事件：几乎 `0ms`
- 第一段正文：约 `5609ms`
- 总耗时：约 `6536ms`

#### 结论

简单问题走的是 `direct_answer` 分支，没有检索和 critic 回退。

所以：

- 架构额外开销大约在 `1.5s ~ 2s`
- 主要慢点仍然来自模型本身生成

这说明：

> 对于闲聊/简单问答，架构不是主要瓶颈，只是有一定工作流包装成本。

### 4.2 投研问题

#### 直连 LLM

- 首 token：约 `9475ms`
- 总耗时：约 `11253ms`

#### 完整 Agent

- 第一条步骤事件：几乎 `0ms`
- 第一段正文：约 `17682ms`
- 总耗时：约 `26977ms`

#### 结论

投研问题走的是更完整链路：

- `intent`
- `rewrite`
- `search`
- `answer`
- `critic`

所以：

- 相比直连 LLM，Agent 第一段正文晚了大约 `8s`
- 总耗时多了大约 `15s ~ 16s`

这说明：

> 对于需要 RAG 和评审闭环的问题，慢的主要原因已经不是模型本身，而是“检索 + 额外节点 + critic 二次调用”。

## 5. 结果怎么解读

### 5.1 为什么“第一条步骤事件”几乎 0ms

因为 Agent 会先发：

- `accepted`
- `intent`

这类状态事件几乎不需要等正文生成完成。

所以从用户体验上看，系统“有反馈”其实很快。

### 5.2 为什么“第一段正文”会慢很多

因为真正的正文必须等前置动作完成：

1. 意图判断
2. query 改写
3. 检索
4. 证据拼接
5. 再进入 answer 节点流式生成

这几个步骤叠加起来，就会让首段正文明显变慢。

### 5.3 为什么复杂问题 Agent 会比直连慢很多

因为 Agent 不是“多包一层函数”，而是多做了真实工作：

1. 额外 LLM 调用
2. 检索器调用
3. 排序融合
4. critic 评审
5. 状态更新和事件流转

这些都是真实成本。

## 6. 当前最重要的结论

### 结论一

简单问题的慢，主要还是模型本身响应速度。

### 结论二

复杂投研问题的慢，架构层确实贡献了明显额外耗时。

### 结论三

这不是坏事，而是“更可靠回答”换来的成本。

换句话说：

- 直连 LLM 更快
- Agent 更慢但更像一个认真做事的系统

## 7. 下一步优化方向

如果后面要优化复杂问题响应速度，优先级建议如下：

1. 优化 `search` 阶段耗时
2. 降低 `critic` 触发或让 critic 更轻量
3. 给简单问题更积极地走 `direct_answer`
4. 对 RAG 结果做更严格裁剪，减少 answer 节点输入长度
5. 针对部分问题提供“快速模式”和“深度模式”

## 8. 一个很适合面试的总结

> 我们做过直连大模型和完整 Agent 的基准对比。简单问题场景下，Agent 只比直连多大约 1 到 2 秒，说明主要耗时仍在模型本身；而复杂投研问题场景下，Agent 因为引入了 rewrite、search、answer、critic 等环节，总耗时会显著增加。这说明架构层确实带来了成本，但换来了更强的证据链和质量控制能力。
