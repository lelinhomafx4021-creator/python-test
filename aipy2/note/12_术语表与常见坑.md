# 12 术语表与常见坑

## 1. 这篇是干什么的

这篇不是讲完整架构，而是帮我们把学习过程里最容易混的词和最常踩的坑一次讲清。

如果你是初学者，这篇会非常有用，因为很多时候不是代码太难，而是术语没对上。

## 2. 核心术语表

### 2.1 LLM

Large Language Model，大语言模型。

在这个项目里，它不是单独完成所有事，而是被放在工作流节点里使用。

### 2.2 Agent

不是单纯“一个模型接口”，而是带有：

1. 状态
2. 决策
3. 工具调用
4. 流程控制

的智能执行体。

### 2.3 LangGraph

一个适合表达有状态工作流的框架。

它适合：

1. 节点编排
2. 条件路由
3. 回退重试
4. checkpoint

### 2.4 AgentState

整条 Agent 流程共享的上下文对象。

你可以把它看成“工作流公共内存”。

### 2.5 RAG

Retrieval-Augmented Generation，检索增强生成。

先查资料，再基于资料回答。

### 2.6 Tool

原子能力模块，比如查询行情、做向量检索、做 web 搜索。

### 2.7 Skill

更高一层的能力编排，会组合多个 tool 形成更完整业务动作。

### 2.8 SSE

Server-Sent Events，服务端推送事件。

适合“后端持续往前端推消息”的场景。

### 2.9 Checkpoint

工作流运行状态的持久化快照，不等于业务聊天记录。

### 2.10 `content_delta`

正文增量事件。前端靠它实现边生成边显示。

## 3. 初学者最容易混的 5 组概念

### 3.1 Tool 和 Skill

- Tool 偏原子动作
- Skill 偏组合能力

### 3.2 工作流节点 和 多智能体

- 节点多，不代表多智能体
- 多智能体强调角色独立协作

### 3.3 聊天记录 和 Checkpoint

- 聊天记录偏业务审计
- Checkpoint 偏运行时恢复

### 3.4 阶段流 和 正文流

- 阶段流告诉你系统跑到哪一步
- 正文流告诉你答案内容本身在增长

### 3.5 输出 token 限制 和 全流程预算

- `max_completion_tokens` 只控单次输出
- 全流程预算要靠状态累计和路由判断

## 4. 常见坑一：看到 `async def` 就以为全异步

不是。

如果在 `async def` 里直接调用同步阻塞代码，比如：

1. `requests.get()`
2. 同步数据库驱动
3. `time.sleep()`

那它依然会卡住事件循环。

## 5. 常见坑二：看见没被当前主链路 import 就以为能删

不是。

Agent 项目里很多代码属于：

1. 初始化能力
2. 迁移能力
3. 回退能力
4. 扩展位

这些都不能简单按“当前直接引用关系”来删。

## 6. 常见坑三：以为流式就是模型自动一边吐字

不是。

真正的流式链路通常要经过：

1. 模型层
2. Graph 层
3. Python SSE 层
4. Java 网关层
5. 前端事件消费层

任何一层处理不好，页面就不像流式。

## 7. 常见坑四：把路由问题和回答长度问题混在一起

比如：

1. 问题被判成 `direct_answer`
2. prompt 又限制成 1-3 句

最后你看到“回答为什么这么短”，其实是两个因素叠加：

- 路由分支
- prompt 限制

## 8. 常见坑五：把 provider 切换理解成只改模型名

不够。

切供应商通常还会涉及：

1. key 名变化
2. base_url 变化
3. 参数兼容变化
4. 流式支持差异

所以才需要 `llm.py` 这种适配层。

## 9. 这一篇你最该记住的结论

1. 学 Agent 时，很多困难其实来自术语混淆。
2. 先把概念边界分清，再看代码，理解速度会快很多。
3. 会踩坑不可怕，关键是知道坑的类别和原理。
