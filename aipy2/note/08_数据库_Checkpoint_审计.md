# 08 数据库、Checkpoint 与审计

## 1. 为什么 Agent 项目常常不止一个数据库角色

初学者容易把数据库理解成“只是存用户聊天记录”。

但在 Agent 项目里，数据库经常要承担多种职责：

1. 业务审计
2. 向量检索
3. checkpoint 持久化
4. 会话记忆
5. 可观测与回放基础

## 2. `app/core/db.py` 在干什么

它通常负责：

1. 创建数据库 engine
2. 提供 session 工厂
3. 给 ORM 和业务层统一提供连接基础

这层的价值不是炫技，而是让“连数据库”这件事标准化。

## 3. 为什么 Engine 和 Session 要分开理解

### Engine

更像“连接数据库的工厂和底层能力”。

### Session

更像“本次业务操作的会话上下文”。

如果用 Java 比喻：

- Engine 类似数据源和底层连接能力
- Session 更像某次事务里的 ORM 操作上下文

## 4. `ChatTurn` 模型为什么重要

它不只是一个聊天表，而是审计基础。

它的价值包括：

1. 记录用户问题和 AI 回答
2. 支持回看历史
3. 支持问题排查
4. 后续可以做评测和重放

Agent 项目如果完全不落审计，后期几乎没法排问题。

## 5. 向量表为什么也是数据库能力的一部分

RAG 不只是“代码检索函数”，它背后需要真实存储结构：

1. chunk 文本
2. metadata
3. embedding 向量
4. 索引

所以数据库在这个项目里还承担知识库底座的角色。

## 6. Checkpoint 是什么

Checkpoint 可以理解成：

- LangGraph 工作流运行时状态的持久化快照

它的意义是：

1. 支持复杂图运行恢复
2. 支持更稳的状态管理
3. 为长链路、可追踪、可中断恢复提供基础

这不是所有小 demo 都有的，但它是更工程化的 Agent 能力。

## 7. 为什么 checkpoint 和普通聊天记录不是一回事

### 聊天记录

偏业务数据，给用户看、给产品用。

### checkpoint

偏系统内部状态，给 Agent 运行时和恢复机制用。

两者价值不同，不要混为一谈。

## 8. 初始化表结构为什么不能轻视

像：

1. 审计表
2. 向量表
3. checkpoint 所需结构

这些如果没准备好，系统通常会：

- 启动后第一次请求报错
- 某些能力静默失效
- 流程看起来能跑，但后台不断异常

所以初始化能力本身就是核心代码。

## 9. 这一篇你最该记住的结论

1. Agent 项目里的数据库，不只是“存聊天记录”。
2. checkpoint 是运行时状态持久化，不等于业务历史。
3. 初始化表结构和连接工厂，是主链路基础设施，不是可随便删的边角料。
